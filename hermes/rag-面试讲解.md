# BlastGame RAG 项目 — 面试讲解材料

> 这份文档是**面试用**的，与实际代码（`hermes/rag/`）分离，方便你复习和讲解。
> 实际代码是干净工程代码，不含任何面试说明。

## 一、项目一句话介绍

为 BlastGame 游戏项目的文档（Doc/MainGame 等约 450KB 模块说明）搭建了一个**本地语义检索工具**：文档 → 切块 → BGE 转向量 → FAISS 检索 → 带来源返回，并加上了 BM25 + 向量混合检索（RRF 融合）。

## 二、成长弧线（最值钱的叙事）

- 我已有 BlastGame **多 agent 调优系统**，做的是**结构化数据检索 + 可靠性筛选**（find_best_combo 找最优档位、filter_verified 数据分级、时间防线防过期）
- 这个 RAG 项目是**从结构化检索扩展到非结构化文本语义检索**——同一套检索思维的升级
- 面试讲法："我从 BlastGame 的结构化数据检索，扩展到 RAG 的语义检索，这是同一套检索思维的连续升级。"

## 三、数据源选型（约束 vs 知识二分法）

核心原则：**"违反了会出事的" = 约束，始终加载，绝不进 RAG；"理解了更好、丢了少点上下文" = 知识，进 RAG。**

| 文件 | 处置 | 理由 |
|------|------|------|
| AGENTS.md / CLAUDE.md / AgentRules | 始终加载 | 规则/约束，召回失败=无约束乱动 |
| Doc/MainGame（63 文件 327KB） | 进 RAG | 各系统模块说明，叙述性，语义检索主场 |
| Doc/Bot / Tools / GuideModule | 进 RAG | 叙述性/工具说明 |
| board / timeline / 池子 / 判定规则 | 不进 RAG | 结构化精确数据，RAG 引入噪声+stale |
| memories/ 过期快照 | 必须排除 | 毒源 |

**反直觉点**：不是"重要的放 RAG"，而是"一秒钟都不能缺的放上下文，缺了也无妨的才放 RAG"。

## 四、技术栈与每层决策（面试核心）

### 1. Embedding：BGE-small-zh-v1.5
- 中文效果好、轻量（512 维）、本地跑
- **关键：BGE 检索是不对称的**，query 必须加指令前缀
  `"为这个句子生成表示以用于检索相关文章："`，passage 不加。不加检索效果明显变差。
- 面试考法："为什么 BGE query 要加指令？" → 因为 BGE 是不对称训练，query 与 passage 分布不同。

### 2. 向量库：FAISS + IndexFlatIP
- **FAISS 没有原生余弦索引**，只有内积（IndexFlatIP）
- **余弦 = L2 归一化后的内积**：先对向量做 L2 归一化，再 IndexFlatIP，就是余弦相似度
- 面试考法："FAISS 里怎么算余弦？" → "归一化后内积 = 余弦"

### 3. 切块：语义切分
- 按 markdown 标题（#/##/###）切成"语义单元"，一条标题段落 = 一个 chunk
- 超长（>512 token）再按段落/句子切，**不硬切语义**
- 面试考法："为什么语义切分比固定 512 好？" → 固定切会切断完整语义，语义切分保留概念完整性

### 4. 检索：混合检索（向量 + BM25 + RRF）
- **为什么混合**：向量擅长语义近义，但对精确专有名词（类名/方法名/字段名如 `BlastReplayActionRecord`）不敏感；BM25 精确命中
- **RRF 融合**（Reciprocal Rank Fusion）：score(d) = Σ 1/(k + rank_i(d))，k=60
  - 只看排名不看分数量纲，天然可融合两路
  - 两路都靠前的才是真准
- **实测提升**：recall@1 从 70% → 80%，MRR 0.733 → 0.800（用数据说话）

### 5. 评估：golden QA + recall@k + MRR
- 手工造 golden QA（10~20 条），从原文改写成不同措辞，标注正确答案来源
- 指标：recall@1/3/5、MRR
- 面试考法："你怎么知道 512 比 256 好？" → "我不拍脑袋，建 golden QA 跑消融表，用数据选。"（**要做消融表**，把 chunk_size/top_k/embedding 各取值跑一遍对比）

## 五、最刁钻追问的诚实答案

> "你这语料才几个 markdown 文件，为什么不用 grep？"
> **答**："承认语料小，grep 能覆盖七成。但 RAG 处理的是语义近义改写——文档里写'超参数改了没锁版本'，用户问'配置被覆盖怎么办'，措辞不同 grep 匹配不上。我做 RAG 的价值是补上语义检索能力 + 把每层工程决策（chunk/embedding/索引更新/评估）真正吃透。对生产收益我不吹，讲清设计权衡才是目的。"

## 六、时间防线（增量重建，比 BlastGame 更高级的叙事）

- **错误做法**：源文件改了没重算 → return empty（召回率归零，面试炸）
- **正确做法**：内容 hash 检测变化 → hash 级跳过未变文件 + 变化文件重建索引 → 原子 swap
- 叙事升级："我从 BlastGame 的'配置变了直接作废'，进化到 RAG 的'增量重建保证一致性'——这是更高级的处理。"

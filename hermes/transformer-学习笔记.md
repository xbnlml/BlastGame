# Transformer 学习笔记（应用开发者视角）

> 内容来源：卡码笔记《Transformer大厂面试题汇总：应用开发者视角》
> 学习方式：四讲循序渐进（Self-Attention → 多头+位置编码 → 三大架构 → 局限）
> 定位：不做训练、做应用，重点理解"每个概念对开发有什么用"

---

## 一、为什么要懂 Transformer？

不懂架构，优化只能靠"试"；懂了架构，你能从原理出发"推"。

| 应用现象 | 底层原因 |
|---------|---------|
| 一次交互消耗几万 Token | 计算量随长度**平方级**增长 |
| 上下文窗口有上限（128K/200K） | O(n²) 复杂度，硬件扛不住更大 |
| 长对话越往后越"忘"前面的 | 注意力机制对长序列的分配问题 |
| 结构化 Prompt 比大段文字效果好 | 多头注意力的分工机制 |

---

## 二、Self-Attention（灵魂）

**一句话**：让每个词去看它和其他所有词的关系，根据关系远近决定关注多少。

经典例子："银行"在"我去银行存钱"是金融机构，在"河边的银行散步"是河岸——**词的意思由上下文决定**。

### Q、K、V（最常考，口诀）
- **Q（Query）**：当前词在**找什么**（"银行"问：谁和我有关系？）
- **K（Key）**：每个词**能提供什么**（"存钱"答：有关系！）
- **V（Value）**：每个词的**实际内容**（确认后拿过来更新）

> **口诀：Q 找对象，K 判断匹不匹配，V 提供实际内容。**

**对开发的启示**：上下文质量 → 注意力分配 → 输出质量。检索质量重要，底层就是它。

---

## 三、Multi-Head Attention（多头）

**为什么单头不够**：一个头只能学一种关系模式，但语言有语法/指代/语义多种关系。

**多头解法**：QKV 复制多份，每份独立算，各学不同关系。8 个头 = 8 个视角（语法/指代/语义/位置...），最后拼起来。分工是训练中自然学会的，不是人设计的。

**对开发的启示**：**结构化不是给人类看的，是给多头注意力看的。** 结构化 Prompt 每个头能快速定位到自己关注的部分。

---

## 四、位置编码（Positional Encoding）

**问题**：Self-Attention 不知道词的先后顺序（"小明打小红" vs "小红打小明"）。

**方案**：
- 正弦编码（老）：简单，超长时表现下降
- **RoPE 旋转位置编码（主流）**：GPT-4/LLaMA 用，外推能力强

**对开发的启示**：长对话质量下降，不只是上下文多，还和位置编码外推能力有关。

---

## 五、三大架构（GPT/BERT/T5）

| 维度 | Encoder-Only | Encoder-Decoder | Decoder-Only |
|------|-------------|-----------------|--------------|
| 代表 | BERT | T5、BART | GPT、Claude、LLaMA |
| 注意力 | 双向 | 双向+单向 | 单向（因果） |
| 擅长 | 理解/分类/抽取 | 翻译/摘要 | 生成/对话/推理 |
| 生成 | 弱 | 强 | 最强 |

### 为什么 Decoder-Only 一统天下？（必考）
1. **Scaling 效果最好**：架构简单统一，规模越大优势越明显
2. **生成和理解都能做**：通过 Prompt 也能做理解，而 Encoder-Only 做不了生成
3. **训练更高效**：目标统一（预测下一个 Token）

### 大模型本质 = 续写
- Prompt 末尾指令特别重要（决定生成方向）
- Few-shot 有效（续写出类似格式）
- System Prompt 放开头（定基调）

## 六、四大局限

### 1. O(n²) 计算复杂度（最核心）
序列翻倍 → 计算量翻四倍。解释了 Token 计费、上下文上限、长对话变慢。
**启示**：控制上下文长度 = 控制计算复杂度（不只是省钱）。

### 2. 位置编码外推问题
训练时没见过的位置不可靠。缓解：RoPE / YaRN / 滑动窗口。但都是缓解不是根治。

### 3. 中间迷失（Lost in the Middle）
对输入**中间**部分关注度低。开头对所有后续有影响，结尾离生成近。
**启示**：关键信息放开头/结尾，别放中间。

### 4. 生成是串行的
一个 Token 一个 Token 来。Speculative Decoding 只能加速不能根治。
**启示**：生成比理解慢，大量输出要流式返回。

## 七、最常考面试题（应用视角）

**Q：为什么现在大模型都用 Decoder-Only？**
> Scaling 效果最好、生成和理解都能做、训练更高效（目标统一）。

**Q：了解 Transformer 对应用开发有什么帮助？**
> O(n²) 让我知道为什么上下文管理重要；位置编码让我知道关键信息放开头/结尾；多头让我知道为什么结构化 Prompt 有效；Decoder-Only 让我知道为什么末尾指令重要。不懂架构优化只能靠试，懂了有据可依。

**Q：O(n²) 复杂度怎么应对？**
> 控制上下文长度（只给相关代码）、模型路由（长窗口用大模型）、关键信息前置（避免中间迷失）、流式返回（缓解串行瓶颈）。

**Q：为什么 Prompt 末尾指令影响最大？**
> 生成本质是续写，末尾指令直接决定续写方向；且距离生成位置最近，注意力权重天然更高。

---

## 八、核心一句话总结

> **Transformer 的架构决定了大模型能做什么、不能做什么、擅长什么、弱在哪里。** 不懂架构用模型只能靠经验"试"，懂了架构能从原理出发"推"。

# 探针设计

## 核心流程（每关独立设计）

**输入：** 关卡号、该关目标胜率（5档）、该关 stage-data
**输出：** 5 槽探针参数（sd/sc/ratios/of），全部参数必须满足硬约束

```
1. 读目标：从 lv_win_config_test.xlsx 读 T1~T5 目标
2. 读池子：从 stage-data/{lv}/ 读全部可靠数据
3. 逐段评估：对 T1~T5 每个段检查池中有无接近的配置（差距 ≤5pp 视为已覆盖）
4. 算缺口：列出未覆盖的目标段
5. 分配槽位：5 槽全部给缺口段
   - 1 个缺口 → 5 槽全打
   - 2 个缺口 → 大缺口 3 槽 + 小缺口 2 槽
   - 3+ 缺口/无数据 → 宽谱覆盖全段
6. 设计参数：每个参数必须满足硬约束（sc=ratios个数）
7. 写入 probe_configs.json
```

> 每关只根据自己的数据独立设计，不存在「跨关分配槽位」。

---

## 缺口评估方法

### 关键：WR 值是百分比 NOT 小数

bot 数据中的 WR 字段是百分比格式（如 81.25 表示 81.25%），目标值也是百分比（如 90.0 表示 90%）。
**两者直接比较，不要除 100。**

```python
# ❌ 错误：目标多除了100
t = tiers[idx] / 100     # 0.9
gap = abs(r['wr'] - t)  # r['wr']=81.25, t=0.9 → 80.35 → 8035pp ❌

# ✅ 正确：直接比
t = tiers[idx]           # 90.0
gap = abs(r['wr'] - t)  # r['wr']=81.25, t=90.0 → 8.75pp ✅
```

### 逐段检查步骤

1. 读取该关全部 bot 数据（`pool.get_preferred_records(lv)` 后过滤 source=='bot'）
2. 对每档目标，找最接近的 bot WR
3. **差距 ≤5pp → 已覆盖**，不分配槽位
4. **差距 >5pp → 缺口**
5. 按缺口数量和大小分配 5 槽
6. 分配完再确认：每个探针是否都是 **NEW config**（不在 bot400 中）

### Normal 难度特殊处理

Normal 只有 3 个有效档位：T1=T2（目标相同）、T3（独立目标）、T4=T5（目标相同）
- 检查 3 个点，不是 5 个
- 展示和分配也按 3 档

## 参数设计方法

对每个缺口段，按以下步骤设计探针参数：

### sd（StartDifficulty）
- 范围：0~50，整数
- **不保证单调**：sd=34 可能比 sd=33 高 53pp
- **每关必须先探方向**：sd↑ 可能 WR↑（倒挂）、WR↓（正常）或 WR→（无效）
- 先用极端值摸范围，再在边界内精调

### SuperHard（difficultyLevel=2）注意事项

SuperHard 等级的参数行为与 Normal/Hard 有显著差异，以下为 L98 实测发现：

- **sd 可能倒挂**：Normal 下 sd↓=WR↑，但 SuperHard 下 sd 的 2 点变化可导致 44pp 的 WR 跳变（sd=20→46.8%，sd=22→2.5%），且方向不一定可预测
- **平滑 ratios（1,2,3,5,5）在 SuperHard 下反而更难**：与直觉相反，均匀的过渡分布会显著降低 WR。反而极端的 1,10,10,10,1 模式表现更好
- **参数空间尖刺**：SuperHard 的 WR 峰值非常窄，微调 1-2 点 sd 就可能从 46% 跌到 3%。应使用更小的步长（1-2 点 sd，0.05-0.1 of）
- **of 影响范围有限**：SuperHard 下 of 变化通常带来 0.5-2pp 的变化，远小于 Normal 下 of 的 57pp 跳变
- **T5 存在最佳 sd 点**：L98 T5 测试中 sd=5→6.0%，sd=8→7.0%，sd=10→0.5%。超出最佳点后 WR 急剧下降
- **多轮不出效果不意味改关卡**：由于参数空间尖刺，SuperHard 可能需要更多轮次逼近最佳点。先用粗略边界缩小范围，再用小步长精调

### sc（ShuffleSplitCount）
- 默认 5，非必要不改
- 降低 sc（3/4）可显著降低 WR（实测 sc=5→3 跳 26pp）
- 但 sc=5 + 极端 sd 扫不出目标段时，才考虑换 sc
- **sc 的值必须等于 ratios 中逗号数 + 1**

### ratios（ShuffleSplitRatios）
- 全相同值等价：`10,10,10,10,10` = `1,1,1,1,1`
- 真正有效差异在段间比例变化
- **高 WR 区**选前段重（`10,1,1,1,1` / `10,10,10,1,1`）
- **低 WR 区**选后段重（`1,1,1,10,1` / `1,1,1,1,10` / `1,1,1,10,10`）
- ratios 对 WR 的影响可能远大于 sd

### of（ShuffleOverflowFactor）
- 范围：0.01~1.0
- **高度非线性**：0.5→0.4 可跳 57pp（临界点在 0.4-0.5 之间）
- 可能倒挂（of↓=WR↓）、可能死区（0.11-0.80 全无效）、可能无响应
- **策略**：先用边界值（0.01 和 1.0）探方向，再小步长（0.02-0.05）精调

## 探针设计中的常见错误

| # | 错误 | 正确做法 |
|---|------|---------|
| 1 | 没读缺口评估直接凭感觉分配槽位 | 先跑数据看每档 gap 是否 ≤5pp |
| 2 | 放了已验证的 bot400 数据 | 探针只放未验证的 phase2/phase1 或全新设计 |
| 3 | 对 L98（仅 T1 缺口）还分配槽位给 T2/T3 | 1 个缺口 → 5 槽全打，不打已覆盖的档位 |
| 4 | WR 计算时目标多除了 100 | 直接比，不要除 |
| 5 | 同一关内 5 槽探针 key 重复 | 5 槽 (sd+ratios) 全部不同 |
| 6 | sc 和 ratios 不匹配 | sc=ratios 逗号数+1 |
| 7 | 不带 pre-task-checklist 直接设计 | 动手前查 skill + 参考文件 |

## 调参策略

1. **sc=5 优先**，极端 sd 也扫不出目标段才换 sc
2. **两轮不出效果就换参数**，不在一棵树上吊死
3. **先极端值探边界**，再在边界内精调
4. **四参数全可调，无固定顺序**
5. 微调时**单变量微调**（一次只改一个参数），不要一次性全改
6. sd 调不动时优先换 ratios 或 sc
7. of 2 轮无效 → 停用 of，换方向

### 参数失效判断

| 轮次 | 无进展时应对 |
|------|-------------|
| R2 | 检查是否方向反了 |
| R3 | 换另一个参数继续探 |
| R4+ | 考虑天花板，准备标记改关卡 |

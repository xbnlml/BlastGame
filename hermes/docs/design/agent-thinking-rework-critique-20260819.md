# 独立批判性评审：瘦身版 agent 改造方案

> 评审人：独立 subagent（未附和主 agent 判断）
> 评审对象：`docs/design/agent-thinking-rework-20260819.md` 及主 agent 的瘦身版（保留 3 / 砍 3 / 反思批次触发）
> 结论前置：**主 agent 的瘦身方向对，但砍得不够狠、又留错了东西。** 我给出一个更少的最终版：**正常轮每轮 0 次 LLM 调用，批次结束 1 次综合参谋 + 1 个零成本的确定性边界报告**。

---

## 0. 评审前必须摆到台面的三个事实（决定了整个评审）

1. **memory 文件没有任何消费者。** 全代码库搜索：唯一读写 `agents/*/memory.md` 的是 `curator.py`（写方）；auto_loop 在收尾以 `capture_output=True, timeout=30` 调 curator，输出被吞掉，只记一行 "Curator: pattern analysis complete"。**没有任何代码回读 memory**。所谓"delegate_task 时注入 agent memory"是主 agent 手动行为，不是流水线。
2. **现有"经验积累"已经是垃圾进垃圾出。** judge memory「边界案例」区 = 13 条 "本轮出现 N 次 gap不足: gap不足"（空洞计数，无关卡号、无数值）；warden memory「最近安全事件」= 20+ 条"阶段顺序异常 ['1','3','5'...]"，那是 `curator.supervise()` 一个坏正则（多轮多关日志必然不等于 `['1','3','5']`）**挂了半个月的误报，没人修、没人发现**。curator memory 有 30+ 条几乎逐字相同的"本轮结果（错误: 1）"。
3. **主 agent 本身就是 LLM，且是唯一的人类接口**（skill 铁则："主 agent 只负责转述"，每轮结束读 `auto_loop_round_report.json` 展示给用户）。因此任何"LLM 解读→给人看"的产出，**都在和主 agent 自己的转述重复**。

由这三条推出的总判断：**本系统缺的从来不是"更多 LLM 解读"，而是"无人值守批次结束后给用户的综合简报 + 卡壳时的第二意见"——这两件是确定性脚本给不了、主 agent 又不会主动做的。其余所有"思考点"要么与主 agent 重复、要么没有消费者、要么是在给坏的检测器上叠 LLM。**

---

## 1. 挑战"保留的 3 项"

### 1.1 Curator 统计→解读 —— 我砍（主 agent 保留 ✗）

- **解读的对象本身就是坏的**：`detect_patterns()` 把整轮日志塌缩成纯计数（"gap不足: 16"），连关卡号、gap 数值、reasons 详情都丢了。给一个 16 次的空洞计数做 LLM 解读 = 在沙子上盖楼。真正完整的数据（每关探针/实际 WR/判定/边界）**已经在 `auto_loop_round_report.json` 里**，curator 的计数器只是它的劣化副本。
- **没有消费者**：解读写进 memory 反思区，而 memory 无人回读（事实 1）。主 agent 读的是 round report，不是 curator memory。
- **与主 agent 重复**（事实 3）：用户问"本轮怎么了"，主 agent 自己就会读 round report 总结。
- 结论：砍掉"对计数器做解读"。如果系统需要解读，消费方只能是用户，解读对象只能是 round report（见最终方案 §4.1）。

### 1.2 探针离线 A/B 回测 —— 主 agent 保留，但这是伪验证（部分同意、必须改 ✗→△）

- **意图是对的**（让数据而不是 LLM 自评来判断 LLM 有没有用），这是整个方案里唯一客观的评估。但机制站不住：
  - 离线重放的 LLM 臂配置**从未在 Unity 里跑过**，它的实际 WR 是**不可知的**。你算不出"LLM 方案的命中率"，因为没有它跑出来的 WR 数据。脚本臂有真实结果，LLM 臂没有——这不是 A/B，是"已知 vs 未知"。
  - 除非你把 LLM 建议的配置真的重放一遍 Unity 批次——那就回到在线成本，且 400 局/档的成本正是用户敏感的。
- 能离线算的只有**廉价代理指标**：① LLM 建议与 `probe_blacklist.json`（已证明失败/被 W09 拦的配置）的重叠率——"LLM 是否在推已知垃圾"；② LLM 建议方向与后续成功轮次实际收敛方向的吻合度——"系统最终是不是走向了 LLM 说的方向"。
- 结论：**保留 `probe_hitrate.json` 记账（纯脚本，不依赖 LLM，本身就有用：探针质量的真实数据，也是卡壳触发的依据），砍掉合成式离线 A/B，改为"黑名单重叠率 + 生产采纳→后验"的自然实验**（见 §4.3）。

### 1.3 Judge 边界挑案例（LLM 推荐）—— 主 agent 保留，我改判为"确定性报告，砍 LLM 推荐"（✗）

- **检测不需要 LLM**：灰色地带的判定条件完全是确定性的（gap ∈ [ok_lo−tolerance−3, ok_lo) 之类），judge_level 的 reasons 已经把边界案例打出来了（"gap=9.9<10pp (接近)"），phase_review 每关都打印 reasons[:3]，round report 也带。LLM 在"挑"这件事上零增量。
- **LLM 推荐"判哪态"是错误的产品**：这个系统的 20 天历史证明，边界案例的正确处理方式是**用户裁定 → 变成规则**（L152→near_tolerance_pp=1、L54→tolerance_pp=2、L153→用户裁"接近"、L158/L188→dev=10 贴线算接近）。用户反复强调"标准里没有的指标不许用"、"判定永远用通关率"。LLM 猜"这关该判合格还是接近"就是在制造**标准外的个案裁决**，恰好是用户最反感的漂移方向。
- **它和主 agent 重复**（事实 3）：用户问"L153 为什么是接近"，主 agent 自己会解释。
- 结论：LLM 不推荐判定。替代品是**确定性边界报告**（每轮自动收集所有容差带内案例 + 精确数字 + 对应历史规则，随 round report 给人看）——比 LLM 挑更诚实（用户自己会裁，且裁完变规则），成本为零。

## 2. 挑战"砍掉的 3 项"

### 2.1 Planner 入口参谋（主 agent 砍）—— 同意砍每轮版，但砍过头了（△）

- 每轮"这关问题是什么、下轮修哪"——90% 的轮次答案可从 round report 确定性得出（缺口就是 reasons 里的 gap 行），且与主 agent 转述重复。砍每轮版，同意。
- **但原方案 §3.2 自己点出的最高价值场景被一起砍掉了**："同一缺口两轮都没修好，该换思路"（L163 教训）。这正是脚本的死角：反推法/缺口驱动在**局部打转**时没有跳出机制。`round_no_progress` 黑名单机制已存在（auto_loop.py L940-959），触发条件**今天就能算**：某关连续 ≥2 轮黑名单新增且 WR 未动 → 该关陷入循环。这个"卡壳换思路"升级参谋是全部 6 个思考点里**唯一有真实空缺、真实决策链、真实后续动作**的一个（建议采纳后走既有 Warden 闸门，闭环存在）。
- 结论：每轮参谋砍（同意）；"卡壳换思路"升级参谋**要留**，合并进批次综合参谋（§4.2）。这是与主 agent 的分歧点之一。

### 2.2 探针审校每轮（改触发式）—— 同意改触发，但触发要具体化 + 不许"落盘即死"（△）

- 同意去掉每轮审校。但触发条件必须**可计算、稀有、高价值**，原方案只说"灰色地带/模糊案例"太含糊。明确三条确定性触发：① 探针产出 0 或可达性阻断；② covered 但组合拼不出（L163 型，`plan_specs` 认为覆盖、`find_candidates` 无可行候选）；③ 同一缺口段连续 2 轮未修好（与 2.1 同一触发）。
- 更大的问题：原方案说"无人值守时只落盘不生效"——这意味着审校结果 95% 时间进 advisor 目录**等死**（和 memory 一个下场，事实 1）。**凡是"落盘即死"的产出就是浪费**。审校必须挂到"卡壳升级"同一事件上，产出直接进给用户的批次简报，而不是独立每轮跑完写文件。
- 结论：保留"触发式审校"，但触发 = 上述三条之一，且并入卡壳升级通道。不保留独立触发。

### 2.3 Warden W10 改法建议（主 agent 砍）—— 完全同意（✓）

- W10 的 warn 消息本身就含改法方向（"目标 80% 缺口但探针 sd=30 偏难，应低 sd/of"）。LLM 重述一遍零增量。
- W10 的真正问题是**warn 不 block、消息被忽略**（warden memory 里探针被 W09/W10 打回的记录不少，但这是闸门在正常工作）。那是策略问题（要不要升 block / 要不要人看），不是 AI 问题。砍得对，无分歧。

## 3. 反思节奏：主 agent"批次结束或人工触发"——大方向对，但用错机制

- 每轮反思的问题清单本身有一半是废话："warden 本轮有无 W10 warn"——答案确定性可得；"judge 我的建议准不准"——规则没变就无可校准，除非用户改裁（有日志）。**按 agent 各问一条 = 仪式感，不是思考。**
- 正确做法是**异常驱动**：正常轮（探针命中、判定通过、无 warn、无错误）不产生任何值得反思的信号，零调用。真正值得 LLM 反思的问题只有两个，且都对应可计算的异常：① **卡壳轮**：方向为什么错、替代方向是什么（触发 = round_no_progress 黑名单增长）；② **用户改裁/新裁定**：这暗示了什么规则空白（触发 = 用户对边界案例的裁决与规则不符）。
- 而这两个异常**不需要单独的每轮反思钩子**——确定性异常检测器（零 LLM）在批次结束汇总时就把异常轮捞出来了。所以最终形态是：**正常轮每轮 0 次 LLM 调用；批次结束 1 次综合参谋（内含异常轮复盘）**。比主 agent 的"批次结束"更彻底：不是"批次结束反思所有轮"，而是"批次结束反思被检测器捞出的异常轮"。
- 反思产出**不进 memory 反思区**（无消费者），进批次简报 + 规则演进建议（有消费者：用户/主 agent）。

## 4. 最终版方案：最有价值、最少浪费

**一句话：正常轮每轮 0 次 LLM 调用；无人值守批次结束或每 N 轮，跑 1 次"综合参谋"，外加每轮 1 个零成本确定性边界报告。全部 LLM 产出都有真实消费者，没有任何"落盘即死"的输出。**

### 4.1 保留 1：确定性边界报告（零 LLM，替代"Judge LLM 挑案例"）

- 纯脚本：每轮 round report 自动收集所有"容差带内判定"案例（gap/dev 落在 tolerance 带内或贴线），按关列出：精确数值 + 现行规则 + 对应历史案例锚点（L152/L153/L54/L158）。
- 消费方：用户 + 主 agent。**用户对边界案例的裁定回流成规则**（这正是系统 20 天来一直在做的、唯一被验证有效的进化路径）。
- 为什么不用 LLM：检测确定性可得、LLM 推荐会制造标准外个案裁决、与主 agent 解释重复（见 §1.3）。
- 附加价值：这个报告同时是 §4.2 卡壳检测和 §4.4 规则建议的**确定性输入**。

### 4.2 保留 2：批次综合参谋（每批 1 次 LLM 调用，替代"Curator 解读 + Planner 参谋 + 探针审校 + 反思"四合一）

批次结束（auto_loop 停/完成，或每 N 轮 checkpoint）触发，LLM 一次性读：全批次 round report + probe_hitrate 记账 + 黑名单 + 边界报告 + 用户改裁日志。产出三样，**全部有消费者**：

- **A. 给用户的批次简报**（≤150 字）：本轮/批发生了什么、哪些关待确认入库、哪些待确认改关卡、哪些边界案例需要看、哪些关卡壳。消费方：用户（无人值守跑完后回来看的那个人）。这正是主 agent 不会主动做、确定性脚本给不了的"跨轮综合"。
- **B. 卡壳关换思路建议**（仅当 4.2 的卡壳触发命中，≤150 字/关）：连续 ≥2 轮无进展的关，LLM 读该关近几轮探针轨迹 + 黑名单 + 缺口分析，给替代方向。消费方：主 agent/用户，采纳后走既有 Warden 闸门 + 下一轮验证。**这是唯一有真实决策链的 LLM 点。**
- **C. 规则空白建议**（仅当用户改裁或边界反复出现）："边界案例反复落在同一类 → 建议新增/修改一条规则"。消费方：主 agent → 用户确认 → rules.json（单一真源不动，改动仍须人确认）。

正常批次 ≈ 1 次调用（拆 2 次：简报 1 + 卡壳建议 1）。异常多 → 卡壳关多 → 调用多，天然按需。

### 4.3 保留 3：探针有效性记账 + 廉价评估（纯脚本，替代"离线 A/B"）

- `probe_hitrate.json` 照做（每轮回填每槽探针实际 WR vs 目标段）——不依赖 LLM，是探针质量真实数据，也是卡壳触发依据。
- **砍掉合成式离线 A/B**（LLM 臂无真实 WR，伪验证）。评估改为两个廉价代理 + 一个自然实验：① LLM 建议与黑名单重叠率（是否推已知垃圾）；② LLM 建议方向 vs 后续成功轮实际收敛方向；③ 生产采纳→后验：凡被采纳的 B 类建议，下轮看 WR 是否动（数据进 hitrate 表）。这些**数据说话**，证明 LLM 值不值。

### 4.4 砍掉清单（最终）

| 原方案/瘦身版点 | 处置 | 核心理由 |
|---|---|---|
| Curator 统计→解读 | **砍** | 计数器有损 + memory 无消费者 + 与主 agent 重复 |
| 探针离线 A/B 合成回放 | **砍**（留 hitrate 记账 + 廉价代理） | LLM 臂无真实 WR，无法离线算命中率 |
| Judge LLM 边界推荐 | **砍**（留确定性边界报告） | 检测确定性可得；LLM 推荐 = 标准外个案裁决，用户最反感 |
| Planner 每轮入口参谋 | 砍（留卡壳升级版） | 每轮版与 round report 重复；卡壳版是唯一真价值 |
| 探针每轮审校 | 砍（触发并入卡壳升级） | 触发要可计算稀有；"落盘即死"=浪费 |
| W10 改法建议 | 砍（同意主 agent） | warn 消息已含改法方向 |
| memory 反思区 / advisor 落盘即死 | 砍 | 无消费者（全库唯一回读方是写方自己） |
| 每 agent 各问一条的仪式反思 | 砍 | 一半问题答案确定性可得；只留 2 个真问题 |
| llm_advisor.json 每轮 5 次配额框架 | 砍（改"每批 ≤3 次"） | 正常轮不需要 5 次，配额框架是给过量用的 |

### 4.5 反思节奏（最终）

**正常轮：0 次 LLM。异常轮：不单独钩子，被批次结束的确定性检测器捞出，并入批次参谋的 B/C 项。人工可随时触发（--reflect）。** 产出进批次简报，不进 memory。这就是"轻量做法"：不是每轮反思，也不是简单"批次结束反思全部"，而是"只反思被异常检测器捞出的轮次"——成本最低、信噪比最高。

### 4.6 成本对比

- 原方案：每轮 ~5 次（planner 1 + probe 1 + judge ≤2 + curator 1）+ 每轮反思打包。
- 主 agent 瘦身版：每轮 ~3 次（Curator 解读 + 边界 ≤2）+ 批次反思。
- **本版：正常轮 0 次/轮；每批 1 次（简报）+ 卡壳增量（B/C，通常 0-2 次）。** 一个月的调用量约为原方案 1/10，且每个输出都有消费者——这是"最少浪费"的判据。

## 5. 与主 agent 判断的分歧点清单

1. **Curator 统计→解读：主 agent 保留，我砍。** 理由：解读对象（detect_patterns 的计数）有损、memory 无消费者、与主 agent 转述重复。若坚持要"解读"，对象必须是 round_report、消费方必须是用户、且要承认这是在替主 agent 做定期简报（那也应该在批次粒度而非每轮）。
2. **探针离线 A/B：主 agent 保留，我判为伪验证。** LLM 臂配置从未跑过，离线算不出命中率。改为黑名单重叠率 + 采纳后验（生产自然实验），保留 hitrate 记账。
3. **Judge 边界挑案例：主 agent 保留 LLM 推荐，我改确定性报告。** LLM 挑不出规则挑不出的东西；LLM 推荐判定方向制造标准外裁决，与该系统"边界→用户裁定→变规则"的验证路径相悖。
4. **Planner 入口参谋：主 agent 全砍，我保留"卡壳换思路"升级版**（合并进批次参谋）。这是唯一有真实决策链的 LLM 点（触发可算、建议有 Warden 闸门兜底、效果可后验）。
5. **探针审校：主 agent 砍为"触发式"，我同意但补两条**：触发条件必须具体化（0 探针/组合拼不出/同缺口 2 轮未愈三条）；产出必须进卡壳升级通道，禁止"落盘即死"。
6. **反思节奏：主 agent"批次结束或人工触发"，我升级为"正常轮 0 次、只反思异常轮（检测器捞出）"**，且产出进批次简报而非 memory。
7. **无分歧**：W10 改法建议砍掉；每轮探针审校砍掉。

## 6. 给用户的诚实结论

这套系统 20 天的历史已经证明：**它的"智能"不在 agent 的思考里，而在"用户裁定 → 规则化 → 回归测试固化"这条链上**（L152→容差、L158→dev 贴线、L54→tolerance_pp，每一条都是用户裁的）。LLM 在这个系统里唯一不添乱的位置是：**无人值守结束后的综合简报（让用户回来一眼看清该决策什么）** 和 **卡壳关的第二意见（让脚本跳出局部循环）**。其余"让每个 agent 都有思考痕迹"的诉求，要么是给无消费者的目录写文件，要么是和主 agent 重复，要么是给坏检测器叠 LLM——都是浪费。如果一定要满足"每个 agent 有参与感"，最便宜的满足方式是把批次简报里的段落按 agent 署名（"Planner 视角：卡壳分析；Judge 视角：边界清单；Curator 视角：趋势"），让参与感来自真实产出，而不是虚构的每轮思考。

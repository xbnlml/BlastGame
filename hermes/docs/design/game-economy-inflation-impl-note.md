# 数值膨胀系统 — 开发实现说明

## 一、概述

在 BlastGame 中引入主动通货膨胀（通胀），使游戏内金币的购买力随玩家进度逐步下降。核心目的是：蚂蚁森林（被动金币产出）的持续产出不会导致玩家金币过剩，同时为后期推出新关卡和付费礼包留出空间。

## 二、通胀系数

### 2.1 系数表

| 阶段 | 关数范围 | 系数 | 道具价格 | 复活价格 | 关卡奖励 |
|------|---------|------|---------|---------|---------|
| 1 | 1-50 | 1.0× | 1000 | 2000 | 100 |
| 2 | 51-100 | 1.5× | 1500 | 3000 | 150 |
| 3 | 101-150 | 2.0× | 2000 | 4000 | 200 |
| 4 | 151-200 | 2.5× | 2500 | 5000 | 250 |
| 5(未来) | 201-250 | 3.0× | 3000 | 6000 | 300 |
| 6(未来) | 251-300 | 3.5× | 3500 | 7000 | 350 |

### 2.2 规则

- 系数每次 +0.5，可无限扩展（阶段7=4.0×，阶段8=4.5×……）
- **所有金币数值 × 系数**：关卡奖励、Pass 奖励、签到奖励、任务奖励、商店礼包金币量
- 玩家当前阶段由**已通关的最高关卡数**决定（不是当前正在玩的关卡）
- 阶段在进入新关数范围时立即切换

### 2.3 实现

```python
# 伪代码示例
def get_stage_coefficient(cleared_levels):
    if cleared_levels >= 201: return 3.0
    if cleared_levels >= 151: return 2.5
    if cleared_levels >= 101: return 2.0
    if cleared_levels >= 51:  return 1.5
    return 1.0

def get_item_price(base_price, cleared_levels):
    return base_price * get_stage_coefficient(cleared_levels)
```

### 3.2 通用规则（三树共用）

- **每树20级，5个星级**（1★ lv1-4, 2★ lv5-9, 3★ lv10-14, 4★ lv15-19, 5★ lv20）
- **升星效果：** 减少收集间隔、增加单次产出

- **8小时容量：** 最多储存 8×每小时产出 的金币，超出不累积
- **田间变化：** 升星时「每次」增长幅度明显大于同级内升级
- **升级费不乘通胀系数**（固定值）

### 3.5 效率设计原则

- **同级内 C/D 递增：** 1★内 C/D 16→17→18→20（越来越贵）
- **星级间 C/D 不重叠：** 2★最低 C/D=23 > 1★最高 C/D=20，保证后面的星级不会比前面的更便宜
- **升星 C/D 骤降：** 升星 C/D=5→6→7→8（渐增），但远低于同级内升级（16-38），效率提升 4-5 倍
- **C/D 计算公式：** `C/D = 费用 ÷ 新增每日产出`，越低越划算

### 3.6 实现逻辑

```python
# 蚂蚁森林升级数据（每棵树独立配置）
class TreeUpgrade:
    def __init__(self, level, star, interval, pickup, cost):
        self.level = level
        self.star = star
        self.interval = interval  # 分钟
        self.pickup = pickup      # 每次收集金币
        self.cost = cost          # 升级费用

# 升级时更新
def upgrade_tree(tree, current_level, player_gold):
    upgrade = tree.upgrade_table[current_level + 1]
    if player_gold >= upgrade.cost:
        player_gold -= upgrade.cost
        tree.current_level += 1
        tree.interval = upgrade.interval
        tree.pickup = upgrade.pickup
        return True
    return False

# 收集金币
def collect_tree(tree, last_collect_time, now):
    if tree.interval == 0: 
        return 0
    elapsed = (now - last_collect_time).total_seconds() / 60
    max_collects = min(elapsed / tree.interval, 8 * 60 / tree.interval)  # 8h上限
    return int(max_collects * tree.pickup)
```

## 九、复活费用递增

### 9.1 规则

每关最多复活 3 次，每次复活费用递增。

| 次数 | 倍率 | 公式 | 阶段1 | 阶段2 | 阶段3 | 阶段4 |
|------|------|------|-------|-------|-------|-------|
| 第1次 | 1× | 2000 × 系数 | 2,000 | 3,000 | 4,000 | 5,000 |
| 第2次 | 2× | 4000 × 系数 | 4,000 | 6,000 | 8,000 | 10,000 |
| 第3次 | 3× | 6000 × 系数 | 6,000 | 9,000 | 12,000 | 15,000 |

### 9.2 设计意图

- 第1次复活：价格合理，鼓励玩家尝试
- 第2次复活：开始变贵，玩家会犹豫
- 第3次复活：真正贵，玩家只在很想过关时才用
- 3次全复活 ≈ 1天收入（阶段4），是合理的惩罚上限

### 9.3 实现

```python
def get_revive_cost(revive_count, stage_coefficient):
    multipliers = [0, 1, 2, 3]  # 0=没用过, 1=第一次, 2=第二次, 3=第三次
    if revive_count < 1 or revive_count > 3:
        return 0
    return int(2000 * multipliers[revive_count] * stage_coefficient)
```

## 十、关键实现注意事项

1. **阶段切换时机：** 玩家通关第50/100/150/200关后立即切换阶段，关卡奖励和物价同步更新
2. **蚂蚁森林升级费不乘系数：** 固定值，不受通胀影响
3. **8小时容量：** 不收集不累积，防挂机堆金。每次收集后重置计时
4. **动态定价每日刷新：** 每次打开商店时计算当前持金/日收入比率，应用修正
5. **升星特效：** 升星时应有视觉反馈（粒子特效/动画），让玩家感知到"效率大涨"
6. **新玩家保护：** 阶段1的蚂蚁森林升级费已按最终设计设置，新玩家无需额外保护
7. **数据配置化：** 蚂蚁森林三树的升级表应做成可配置的 JSON/表格，方便后续调参

# BlastGame RAG 建法方案 v1（历史提案）

> **已被当前实现取代。** 本文保留最初技术选型背景，不能作为构建或评估说明。现行行为与指标见 `../../rag/README.md`、`../../rag/index/build_manifest.json` 和 `../../rag/index/evaluation.json`。
> 当时目标：通过一个本地知识库原型理解 RAG 各层及其工程取舍。

## 一、为什么做（叙事源头）

- 我已有 BlastGame 多 agent 调优系统，处理的是**结构化数据检索 + 可靠性筛选**（find_best_combo、filter_verified、时间防线）
- RAG 是"非结构化文本的语义检索"，与我已有能力同源，补上后能讲"我从结构化检索扩展到语义检索"的成长弧线
- 做一个真实落地的本地知识库 RAG，用实际数据验证每层决策，而不是只跑通框架示例

## 二、数据源选型（吸取第一轮评审意见）

| 数据源 | 做/不做 | 理由 |
|--------|---------|------|
| wrongbook.md（踩坑教训） | ✅ 做 | 叙述性，语义检索价值大 |
| .hermes.md 规则精华 | ✅ 做 | 描述性知识，agent 查"这件事件该怎么做" |
| review/phase 结论（蒸馏后） | ⚠️ 可选 | 大段分析，只索引"结论"部分 |
| board.md / timeline.md / 池子 / rules | ❌ 硬禁 | 结构化精确数据，RAG 引入噪声 + 过时副本 |
| **memories/ 过期快照** | ❌ **必须排除** | 毒源，会误导 agent，绝不能索引 |

## 三、技术栈（本地、零平台依赖）

- Embedding：`BGE-small-zh`（中文效果好、轻量、本地跑）
- 向量库：`FAISS`（本地文件，无需装服务，数据量小够用）
- Chunk：递归切分，512 token 中文按字换算，overlap 20%
- 检索：Top-K + 余弦相似度 + 相关性阈值过滤
- 时间防线：embedding 带生成时间戳，源文件改了没重算 → 拒绝检索（return empty 不返回 stale）
- 混合 fallback：RAG 检索为空 → 自动降级 `search_files` 关键词搜索
- 集成：做成 Hermes 一个工具命令，agent 可调用

## 四、每层可讲的决策点

| 层 | 可讲清的设计决策 |
|----|-------------------|
| 数据清洗 | 排除过期毒源、白名单索引（呼应"差料出差货"） |
| Chunk | 512 + overlap 20%，为什么不大不小 |
| Embedding | 中文为什么选 BGE，不选通用模型 |
| 检索 | 余弦相似度 vs 欧氏距离，Top-K 设多少 |
| 时间防线 | 源文件改了没重算就拒绝，防止 stale（与 BlastGame 同源） |
| 混合检索 | 语义 + 关键词互为兜底 |

## 五、MVP 范围（半天内可完成）

1. 脚本：读取白名单文件 → 递归切 chunk → BGE 转向量 → 存 FAISS
2. 查询：输入问题 → 检索 Top-K → 阈值过滤 → 输出相关片段
3. 时间防线：记录源文件 mtime，改动后标记 embedding 过期
4. 集成为一个 CLI 命令

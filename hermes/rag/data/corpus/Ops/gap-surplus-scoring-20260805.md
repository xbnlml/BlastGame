# 选择评分：档位差富余奖励（2026-08-05 定稿）

## 用户两次纠正过程（重要，别重蹈覆辙）

**第一次纠正**：我提出"目标偏差要算，但低侧偏好——48%（低侧）好于 52%（高侧）"。用户纠正：
> "不是低侧更优！而是能使档位差变大的更优！如果跟30%比，那52%不就好于48%了吗！"

即：T4=30% 时，T5=52% 的 gap=22 > T5=48% 的 gap=18 → **52% 更好**。低侧/高侧不是关键，**能否拉开档位差**才是关键——方向取决于相邻档位位置。

**第二次纠正**：我按"偏差总和"排序 18 关说需更新 Excel，用户纠正：
> "档位差不看吗？我们不是说档位差比更贴近目标值更重要吗"

后又说：
> "你也不能只看档位差不看离目标的偏差啊！"

即：**档位差（判定 gap）优先，目标偏差作次级参考，两者都要看**——不是只看 gap 也不是只看偏差。

## 最终公式（tools/data/pool.py）

```
target_score = sum(|wr[i] - targets[i]|)          # 权重 1.0，绝对偏差，无方向偏置
gap_score   = _gap_score(wrs, difficulty, targets)  # 原有罚分 + 新增富余奖励
q = target_score + source_score + gap_score + death_score
```

`_gap_score` 内新增（gap 已合格时）：
```python
else:  # g >= ok_lo
    surplus = min(g - ok_lo, 35 - ok_lo)   # 超出合格线的富余量，35 截断
    if surplus > 0:
        score -= surplus * 0.5             # 富余奖励：拉开档位差有价值
```

## 为什么系数 0.5

- 若奖励系数 = 1.0：`(-5)×1.0 + 富余5×1.0` 与 `(+2)×1.5` 恰好抵消（45% 与 52% 同分）——第一次实现失败（验证 3 断言 `45% < 52%` 不成立，0.4 == 0.4）
- 若奖励系数 = 0.5：拉开档位差有价值（45% vs 52% 选 45%），但目标偏差（权重 1.0）仍是主导（42% vs 50% 同 gap 时选 50%）——**防无限拉低档位**

## 判断"Excel 是否需更新"的标准（2026-08-05 用户确认）

1. **同配置池子有没有新胜率**（created_at 更新）且**不是统计波动**（>5pp 差异）→ 有则 Excel 旧值失效
2. 池子重选组合的**判定（gap 结构）是否优于 Excel 记录**：
   - 不合格/接近 → 合格 = **应更新**
   - 合格 → 不合格/接近 = **保留 Excel**
   - 判定不变 = 不更新
3. 151-200 实测：18 关（偏差标准）→ 按判定标准 8 关应更新（151/157/177/178/179/181/193 + 199 待定：不合格→接近）

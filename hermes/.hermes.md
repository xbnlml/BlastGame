# BlastGame 动手前守则（Hermes 每次自动加载）

> 本项目工作目录为当前 checkout 的 `<PROJECT_ROOT>/hermes`。这个文件由 Hermes 自动注入，**每次动手前先过一遍下面的触发清单**。

## ⚠️ 第一铁则：动手前先查现成工具

**做任何操作（写/查/判/跑）前，先看 `tools/README.md` 的工具索引**——按"你想做什么"查该用哪个工具，禁止手写脚本重复造轮子。

```bash
ls tools/            # 看有哪些脚本
cat tools/README.md  # 按操作类型查工具
```

**最容易犯的（已踩坑多次）**：
- 生成 DB payload → 用 `tools/gen_payload.py --levels X --source <批次>`，**别手写硬编码关卡列表的脚本**
- 写 Excel 入库 → 用 `write_tiers`，胜率列是**小数**（0.8=80%），不是百分数
- 写 asset → 用 `write_ddc` + `verify_asset`，改前算 fingerprint（DB 可能已自动匹配）
- 统一入库 → 用 `reimport.py` / `reimport_batch.py`，别手动三个动作分开做
- **查最优档位/判定 → 用 `tools/judge_level.py "102,110,122"`**（输出 T1->T5+判定+操作），**别写临时脚本查池子**（2026-08-06 又犯：写 hermes-11lv.py 被暴怒）——查单关现状用 `state_snapshot.py --levels`，查 DB 用 `compare_level_db.py`

## 按操作类型（只做哪类就看哪类）

### 写操作（碰 asset / Excel / board / 关卡数据库）
- 先 `ls tools/` + 读 `tools/README.md` 第一节"写操作"
- asset 用 write_ddc，Excel 用 write_tiers，board 用固定 7 列整行替换
- 写前说清影响范围（变哪些/不变哪些/如何回滚）
- 写后 verify / 回读验证

### 查数据 / 分析
- 判定/组合走 `level_status.py` / `find_best_combo.py` / `param_knowledge.py`，别自己从零算
- 只读脚本验证零副作用
- **查游戏文档/模块功能 → 用 `python rag_query.py "问题"`**（对 Doc/MainGame 等游戏文档做语义检索，带来源）。建索引用 `assistant` 跑 `python -m rag.build_index`

### 提交 / 批跑
- 全自动用 `auto_loop.py`，提交用 `submit_batch_unity.py`
- 批前过 Warden（`warden.py`），批后跑 `post_batch_review.py`

## 通用铁则
- **禁止任何 git 命令**（含只读），git 由用户 SourceTree 手动管理
- 破坏性操作（删/改 DB/覆盖）先展示方案等用户确认
- 展示数据先给完整 markdown 表格（含 sd/sc/ratios/of 四参数、难度、来源局数），再分析
- 被纠正立刻认错，不找借口；先展示数据再问下一步
- **改关卡/入库都必须用户确认后才能执行**
